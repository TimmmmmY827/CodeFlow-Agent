# ADR-0001：MVP 使用模块化单体

- 状态：接受
- 日期：2026-08-09

## 背景

项目由一人开发，需要在两周内形成 Windows CLI 演示闭环，同时为模型替换、MCP、多 Agent、长期记忆和桌面端保留合理边界。

## 决策

使用单一 TypeScript/Node.js 仓库和单进程运行时，通过 `src/` 下的明确模块与内部接口隔离职责。MVP 不拆 pnpm 多包、微服务或独立守护进程。

## 原因

- 缩短构建、调试、部署和端到端测试路径。
- 追加式事件仍能让状态边界清晰且可恢复。
- `ModelAdapter`、`ToolProvider`、`EventStore` 等接口足以支持后续替换。
- 避免预先承担版本、网络、发布和跨进程一致性成本。

## 后果

- 所有组件共享同一发布节奏和进程故障域。
- 必须通过依赖方向和测试防止模块耦合，而不是依靠进程隔离。
- 只有出现独立扩缩容、强隔离或发布周期差异的实测需求时，才考虑拆分。
